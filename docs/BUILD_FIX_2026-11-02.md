# Windows startup packaging fix — 2026-11-02

The initial Windows build failed at startup because PyMuPDF's optional layout engine requested a YAML resource that PyInstaller had not included.

## Fix

`build_windows.bat` now passes `--collect-all pymupdf` to PyInstaller, which gathers package data, binary dependencies and submodules. The script then checks that the specific file reported in the Windows traceback exists in the built `_internal` folder before creating the portable archive.

## Rebuild

1. Exit the application/error dialog.
2. Extract this corrected release archive into a *new folder*, not on top of a previous build.
3. Double-click `build_windows.bat` on Windows with an internet connection.
4. Open `dist\PDF Assignment Marker\PDF Assignment Marker.exe`.
5. Verify About says v11.0.0 (2026), icon, open PDF, annotate, save, reopen.
6. If the program still fails, capture the complete new traceback. Some PyMuPDF releases may use a different resource filename; do not move files by hand.

**Scope:** Packaging change only. No application source, approved interface or marking functionality was modified.
